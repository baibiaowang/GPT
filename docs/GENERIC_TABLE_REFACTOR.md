# 通用表格整理转换器重构方案

## 目标

本项目从股票专用展示器升级为通用表格整理转换器。

核心理念：

> App 不理解业务，只理解表格。

任何数据进入 App 后统一转换为：

表头(columns) + 行(rows) + 单元格(cells)

股票只是其中一种表格配置。

---

## 一、表头编号系统

所有表头必须编号管理。

示例：

```
001 股票名称
002 股票代码
003 当前价格
004 判断分类
005 公告时间
006 公告标题
007 判定性质
008 判定总结
```

程序内部使用 columnId，不直接依赖中文名称。

数据结构：

```json
{
  "id":"001",
  "label":"股票名称"
}
```

展示哪些字段，由配置决定。

例如：

```json
{
 "homeColumns":["001","004","005"]
}
```

---

## 二、行数据模型

任何表格统一转换：

```text
Table
 ├ columns[]
 └ rows[]
      └ rowId
      └ cells{}
```

示例：

```json
{
 "rowId":"abc001",
 "cells":{
   "001":"贵州茅台",
   "004":"消费",
   "005":"09-23"
 }
}
```

---

## 三、首页

首页定义：

> 当前表格的快速阅读列表。

不是股票首页。

根据配置展示指定 columnId。

关系：

表头编号 → 单元格内容 → 行列表

---

## 四、类型筛选

类型不是固定 category。

改为通用筛选器：

流程：

选择某个 columnId

↓

扫描该列所有 value

↓

动态生成标签

↓

筛选对应 rows

有多少种显示多少种。

---

## 五、结论筛选

结论与类型同一机制。

不固定：

- 利好
- 不利
- 否决

而是任意表头的值集合筛选。

---

## 六、详情页

详情页不是股票详情。

定义：

> 某一行数据的完整展示。

动态遍历 columns：

字段数量变化不需要修改页面。

---

## 七、收藏与点评

收藏、点评属于本地附加数据。

不能绑定股票代码。

使用：

```
tableId + rowId
```

结构：

```json
{
 "tableId":"xxx",
 "rowId":"abc001"
}
```

远程数据更新不能破坏用户本地收藏和点评。

---

## 八、代码重构顺序

1. 建立 TableModel
2. 建立 ColumnManager
3. 建立 RowManager
4. 建立通用 FilterEngine
5. 首页改为配置驱动
6. 类型/结论改动态筛选
7. 详情页改动态行展示
8. 收藏点评迁移到 rowId
9. 股票功能改为配置文件

---

## 禁止事项

后续禁止继续增加：

- 股票专用字段
- 固定业务分类
- 固定结论值
- 固定详情模板

所有新增能力必须服务于通用表格模型。


## 2.1.0 实施验收

- `www/index.html`：仅 UI 壳，不再叠加旧业务运行时代码。
- `www/core/app-runtime.js`：统一负责 SJ01 → schema v3 → TableModel → UI。
- 表头继续使用稳定 `columnId`，实际取值继续由 `ColumnManager` 动态生成 `Vxxx`。
- 类型与结论页面只负责展示已在设置中选择的表头的动态取值标签。
- 收藏与点评保存表格快照，数据源刷新或缺失时仍可查看本地记录。
- 构建阶段验证旧 v2/v20 标记不存在，并校验运行时版本为 2.1.0 / 2100。
